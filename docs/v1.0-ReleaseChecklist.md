# Learnova v1.0 — Release checklist

Use this before you call the platform “ready for colleges.” It assumes Steps 1–17 are built (they are). This is about **confidence**, not new features.

You deploy yourself — this doc does not push anything for you.

---

## What v1.0 actually is

A full enterprise LMS for one institution at a time:

- Public site (landing, login, register, legal pages)
- Institution admin (structure, people, courses, assessments, gradebook, certificates, reports, settings)
- Faculty and student role dashboards
- In-app notifications + optional email (not a chat product)

**Not in v1.0:** Placements, alumni, fees, HR, CRM, AI chatbot, social feed, marketplace, multi-tenant SaaS billing, video conferencing. Those are v1.1+.

## Before you touch production

### 1. Local sanity (30 minutes)

```bash
pnpm install
pnpm env:check          # frontend/.env.local, backend/.env, worker/.env
pnpm docker:dev         # Mongo + Redis if not already running
pnpm build              # all packages — must be green
pnpm dev                # or three terminals: backend, frontend, worker
```

Open http://localhost:3000 and log in as all three demo roles. Hard-refresh each dashboard a few times — you should see a spinner, not a blank page.

### 2. Automated smoke

With apps running locally:

```bash
pnpm verify:platform
```

Fix anything that prints `FAIL` before staging. If auth rate-limits you, wait a minute and re-run.

Optional deeper local provision test:

```bash
pnpm --filter @learnova/backend exec tsx --env-file=.env src/scripts/smoke-provision.ts
```

### 3. Seed data (if DB is empty)

```bash
pnpm seed:complete
```

## Environment checklist

Three files, never committed:

| File | Must have |
| --- | --- |
| `frontend/.env.local` | `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_WS_URL` |
| `backend/.env` | `MONGODB_URI`, `REDIS_URL`, JWT secrets (≥32 chars), `CORS_ORIGINS` |
| `worker/.env` | Same Mongo + Redis; mirror `MAIL_*` if you want real emails |

Full reference: [Environment.md](./Environment.md).

**Email:** default is console logging. For real notification emails, set `MAIL_DRIVER=smtp` on **both** backend and worker. See [Mail.md](./Mail.md).

**Notifications:** on by default (`ENABLE_NOTIFICATIONS=true`). Worker must be running for queued emails.

## Staging deploy (you do this)

Follow [Deploy.md](./Deploy.md) and [STAGING.md](./STAGING.md). Short version:

1. MongoDB Atlas + Redis (Upstash or Render)
2. Render → API (`backend/`), env from Deploy doc
3. Vercel → frontend (`frontend/`), public URLs pointing at Render
4. Seed staging once: `MONGODB_URI=... pnpm seed:complete`
5. Run smoke against staging:

```bash
SMOKE_WEB_URL=https://your-app.vercel.app \
SMOKE_API_URL=https://your-api.onrender.com/api/v1 \
pnpm verify:platform
```

## Manual walkthrough (do not skip)

Automated tests miss UX. Block an hour and walk through this as each role.

### Institution admin

- [ ] Login → institution dashboard loads
- [ ] Open a course, see enrollments
- [ ] Gradebook overview opens
- [ ] Certificates page — list + verify link works
- [ ] Reports — institution summary loads; try CSV export
- [ ] Settings — save something harmless (timezone)
- [ ] Bell icon — notifications page opens, search works

### Faculty

- [ ] Login → faculty dashboard
- [ ] Open assigned course → assignments / quizzes
- [ ] Gradebook — view entries (no institution admin pages)
- [ ] Try `/institution/students` in URL → blocked (403 or redirect)

### Student

- [ ] Login → student dashboard
- [ ] Courses / progress / assignments visible
- [ ] Grades page shows data (if seed ran gradebook)
- [ ] Certificates — at least one if auto-issue ran
- [ ] Notifications — mark one read, delete one
- [ ] Try `/faculty/gradebook` → blocked

### Cross-cutting

- [ ] Logout → login again → session restored via refresh cookie
- [ ] Hard refresh on dashboard — no blank screen
- [ ] Forgot password page loads (email delivery depends on SMTP)

## Grade → certificate → notification path

This is the “minimal notifications” slice people care about for launch:

1. Faculty/admin publishes grades for a course
2. Students get **grade published** notification (in-app + email if configured)
3. If auto-issue is on, certificates generate
4. Students get **certificate issued** notification

No separate messaging product — just event-driven alerts.

## Production go / no-go

**Go** when all of these are true:

- [ ] `pnpm build` passes on main branch
- [ ] `pnpm verify:platform` passes against staging URLs
- [ ] Manual 3-role walkthrough done once on staging
- [ ] Secrets in host env (not in git)
- [ ] `CORS_ORIGINS` matches your Vercel URL exactly
- [ ] Worker deployed or emails accepted as console-only for day one
- [ ] Backups enabled on MongoDB Atlas

**No-go** if:

- RBAC smoke fails (faculty can PATCH institution settings, etc.)
- Blank screen on refresh still happens
- JWT secrets are short or committed

## After launch (v1.0 maintenance)

- Watch Render logs + MongoDB metrics first week
- Keep demo seed credentials off production admin accounts
- File v1.1 ideas separately — do not expand scope mid-launch
