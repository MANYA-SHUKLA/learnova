# ADR 0004: AI Provider (Gemini)

- **Status:** Accepted
- **Date:** 2026-08-06
- **Deciders:** Platform team

## Context

Learnova includes AI project ideation, assistant features, and future grading/hints. We need a primary LLM provider with a clear swap path.

## Decision

Use **Google Gemini** as the default AI backend:

- API key via `GEMINI_API_KEY` (optional until AI features ship)
- Calls go through a dedicated service boundary (never from the frontend)
- Feature flag `ENABLE_AI` gates all AI surfaces
- Prompts, model IDs, and safety settings live in config — not scattered in controllers

**Why Gemini?** Competitive multimodal pricing, solid Node SDKs, and good fit for ideation + code-aware assistance in an education product.

## Consequences

- Vendor SDK coupling isolated behind an interface (`IAIProvider`) when implemented
- Cost and rate limits must be institution-aware later
- PII redaction required before prompt send (audit + privacy)

## Alternatives considered

| Option | Why not (default) |
| --- | --- |
| OpenAI | Strong alternative; keep as secondary adapter later |
| Self-hosted OSS models | Ops-heavy for foundation; revisit for on-prem institutions |
| Frontend-direct LLM calls | Leaks keys; bypasses audit and rate policy |
