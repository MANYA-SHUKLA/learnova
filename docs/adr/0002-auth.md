# ADR 0002: Authentication & Authorization

- **Status:** Accepted
- **Date:** 2026-08-06
- **Deciders:** Platform team

## Context

Learnova needs multi-role access (Student, Faculty, Institution Admin + reserved roles), multi-tenant `institutionId`, and fine-grained permissions across LMS, exams, IDE, and audit.

Login flows are **not** implemented yet; this ADR locks the contract.

## Decision

| Concern | Choice |
| --- | --- |
| Tokens | JWT access (short TTL) + refresh token |
| Payload | `sub`, `role`, `permissions`, `institutionId`, `sessionId` |
| Sessions | Server-side session metadata in Redis (revocation / device tracking) |
| Authorization | Role → permission matrix in `@learnova/shared` |
| Transport | `Authorization: Bearer` + httpOnly refresh cookie (planned) |

**Why Express middleware?** Thin `authenticate` / `requireRoles` / `requirePermissions` adapters keep controllers free of auth logic and match Clean Architecture boundaries.

**Why Socket?** Socket.io auth will reuse the same JWT verification so IDE/exam realtime shares one identity model.

## Consequences

- Stateless API scale-out with optional sticky sessions only for sockets
- Must rotate secrets via env; dual-secret rotation planned later
- Permission matrix becomes a breaking-change surface — version carefully

## Alternatives considered

| Option | Why not (for v1) |
| --- | --- |
| Auth0 / Clerk / Cognito | Extra cost & vendor lock-in before product–market fit |
| Session-cookie only | Harder for mobile / third-party clients |
| OAuth-only | Institutions still need email/password and SSO later as add-ons |
